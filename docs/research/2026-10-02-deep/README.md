# Gatherline deep investigation — 2 October 2026

**Reviewed application revision:** `a285ee6c8a67e93db01ef2d9046493ea0572a34c`. **Outcome:** a stronger evidence base and an updated [implementation plan](../../IMPROVEMENT-PLAN-2026-10-02.md). Application source and existing tests are unchanged. The scripts here are disposable research harnesses; several deliberately assert undesirable current behavior and therefore passing them does not demonstrate a fix.

The investigation covered server mutation/publication boundaries, native background callbacks, file cleanup, integration queues, client lifetime/history/state publication, real React components, desktop IPC/recovery, packaging dependency collection, emitted worker imports, static HTTP delivery and database query costs. It combines source inspection with real HTTP/WebSocket/filesystem/Electron probes and isolated candidate comparisons. Existing completed optimizations remain in place.

**Integration scope:** documentation was reconciled with newer `main` through `5b0001f`, which adds deferred join/dialog loading, clipboard image paste, notification preview/catch-up and filename/file-kind search. The plan preserves those completed changes. Evidence artifacts remain the original observations at `a285ee6`; neither their test totals nor bundle/query measurements certify the newer integration revision. To repeat an exact historical comparison, use a separate checkout of the reviewed revision with these harnesses; running on later source produces a new experiment, not the same baseline.

## Verification and controls

Fresh baseline builds and checks passed: `pnpm exec turbo run typecheck build --concurrency=2` executed all **seven package typechecks and three production builds** without cache hits. The deeper unit run used `VITEST_MAX_THREADS=2`, `VITEST_MAX_FORKS=2` and `pnpm exec turbo run test --concurrency=2 --force`: **1,533 passed, two skipped**. See [root-validation.json](root-validation.json) and generated package `.turbo/turbo-test.log` files.

The server harness ran **ten children with expected outcomes and no timeout**: three intentional callback failures exited 1; seven controls and other diagnostics exited 0. Client diagnostics passed **six state/lifecycle and three DOM cases**. These are additional investigation cases outside the baseline suite.

Root automation is omitted by package typechecks. A separate strict check found **two real E2E typing errors**, while six existing measurement scripts typechecked: undocumented `WebContents.getLastWebPreferences` access and a Buffer/BlobPart generic mismatch. Green package checks therefore do not establish green automation typing. See [desktop-typecheck.json](desktop-typecheck.json).

The product-native T3 preview completed synthetic-account login, search for `checklist`, navigation to its engineering result, a channel send and a thread reply against the fresh web build and current-source loopback server. At a 390 × 844 CSS viewport, the document width stayed 390 and reply content was present. [Browser observations](root-browser-results.json) retain request statuses and DOM assertions. Snapshot/screenshot calls returned generic preview errors, so no visual screenshot certification is claimed. The narrow viewport uses a desktop user agent, not a physical mobile device. Single navigation and long-task observations are descriptive, not comparative benchmarks. The fixture was stopped and its owned temporary data removed.

Other explicit controls: SQLite `quick_check` passed after callback exits; failed retention transactions restored all 6,001 messages; history late responses were ignored; revoked sessions blocked stale-client mutation; synthetic desktop credentials were encrypted at rest. These controls narrow the findings rather than certifying unrelated behavior.

Fresh web/desktop renderer entry bundles are **493,155 / 494,804 bytes**, below the 500,000-byte guard with only 6,845 / 5,196 bytes of headroom. Docker exists but its Linux engine is unavailable; container build/runtime checks were not performed. Full browser E2E, a fresh installer, clean-machine upgrade/uninstall, physical devices, power loss, browser storage concurrency and representative mixed main-process stalls remain acceptance work.
