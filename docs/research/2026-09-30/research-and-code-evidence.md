## Method and limits

Three parallel source reviews covered client/UI/product, server/data/security and desktop/recovery/release. The root review checked plans, workflows, dependency/runtime versions, existing optimization bounds and pinned T3 Code source. Controlled probes used production helpers, in-memory test servers or isolated temporary fixtures; they did not touch a real workspace. Temporary probe code was not added to the production/test suite. No external application source was executed or installed. No participants were contacted.

Code evidence can show a deterministic failure or missing mechanism. It cannot establish how often users experience it, comparative app performance, installed OS behavior, WAN/phone reliability or formal security/accessibility certification. Proposed features remain hypotheses until a complete user task demonstrates value. Existing dated research remains useful context: [product research](../../PRODUCT-RESEARCH-2026-09-25.md), [hosting models](../2026-09-26/hosting-models-and-positioning.md), and [state tables](../../STATE-TABLES-2026-09.md).

## Dependency and runtime inventory

Fresh registry checks were saved as a [sanitized structured summary](dependency-audit-summary.json). Both audit commands completed and exited nonzero because they reported findings.

| Command/scope              | Reported entries                                    | Interpretation                                                                                                     |
| -------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `pnpm audit --prod --json` | 4 high; 0 critical/moderate/low                     | Two distinct `fast-uri` advisories across locked 3.1.6 and 4.1.3 paths                                             |
| `pnpm audit --json`        | 7 high, 8 moderate, 5 low; 0 critical               | 20 version/package entries representing 14 distinct advisory IDs; includes build/test dependency closure           |
| Current CLI runtime        | Node 24.16.0, SQLite 3.53.0, built-in Undici 7.25.0 | Package-registry audit does not evaluate every dependency bundled into Node/Electron. Trace runtime use separately |
| Desktop lockfile           | Electron 44.1.0                                     | Verify packaged runtime versions and release advisories as part of the support policy                              |

Locked `fast-uri` copies come through Fastify/AJV compilation. Gatherline's outbound policy uses WHATWG `URL` and socket-level DNS checks in [outbound.ts](../../../packages/server/src/outbound.ts), not an observed `fast-uri` allowlist path. The version findings justify patch/triage; no SSRF or authority-injection exploit against Gatherline was demonstrated.

Maintainer advisories identify patched `fast-uri` versions 3.1.7 and 4.1.4 for the two affected lines: [authority injection](https://github.com/fastify/fast-uri/security/advisories/GHSA-qw65-cvwx-89v3) and [host confusion](https://github.com/fastify/fast-uri/security/advisories/GHSA-58mr-gqgx-xq4g). Track both ranges rather than upgrading only one duplicate. The complete audit also reports Vitest/mocker, esbuild and Undici findings. Classify their enabled features and deployment reachability before making claims about shipped exposure. [esbuild's Windows development-server advisory](https://github.com/evanw/esbuild/security/advisories/GHSA-g7r4-m6w7-qqqr) and [Undici's WebSocket subprotocol advisory](https://github.com/nodejs/undici/security/advisories/GHSA-rfgv-xxqx-mfg5) illustrate why package name alone is insufficient for that classification.

SQLite's [current WAL documentation](https://www.sqlite.org/wal.html#walreset) says its rare WAL-reset race is fixed in 3.51.3 and later. The inspected CLI's 3.53.0 is beyond that fix; do not add this as an unfixed local database vulnerability. Validate the independently packaged Electron runtime too. WAL still has filesystem, checkpoint and durability constraints worth measuring.
