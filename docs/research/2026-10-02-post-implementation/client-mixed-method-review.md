# Mixed benchmark method review

Read-only review of [`scripts/measure-mixed.mts`](../../../scripts/measure-mixed.mts) at **`f07ce84362257aedeab16c9ae4c2361193eb6442`**. No runtime, application edits or benchmark rerun performed. Existing [first Windows run](root-mixed.json) and [repeat](root-mixed-repeat.json) are useful observations of their declared workload; they do not complete reference-performance or exact-recovery acceptance.

The repeat has zero counted errors but a **195.95 ms** maximum Node event-loop delay and **227.24 ms** maximum post, versus **51.18 / 60.99 ms** in the first run. Those are observed tails, not proof of one application defect or an Electron-main measurement. Repeat post/fanout round-p95 spread is **61.6% / 63.2%**, so describe the variation and profile before selecting a remedy.

## Other limits relevant to interpreting the tails

- Live workload choices share one PRNG across asynchronous actors ([line 48](../../../scripts/measure-mixed.mts#L48)). The seed reproduces initial fixture distributions, but scheduler/response order changes which actor consumes each subsequent value and how many requests fit in the window. It does not guarantee the exact same offered query/post schedule across candidate builds. Precompute an actor schedule or log and replay one for controlled comparisons.
- Each round awaits roamers and outstanding receipts before disabling the delay monitor ([line 340](../../../scripts/measure-mixed.mts#L340)); end-of-round observations can extend beyond the nominal eight seconds. Actual elapsed duration is not stored. Failed receipt checks can add ten seconds.
- Searches count a successful parsed HTTP answer; only the initial `release` check asserts nonempty seeded data. The timed searches do not assert exact IDs, ACL or hydration. Everything is public and every account is a member, so private visibility/revocation is outside the workload.
- Three maintenance samples are too few for a stable p95; reconnect has roughly 50 samples across three rounds. Samples themselves and request/GC/stall timestamps are not retained, so a max post cannot be correlated with a specific maintenance or GC pause from this artifact alone.
- `Date.now` is replaced during seeding and restored only after the loop ([lines 180–199](../../../scripts/measure-mixed.mts#L180)); a seeding exception would leave the fake clock active through cleanup. Restore it in a nested `finally`. Validate actor/argument bounds: the hard-coded indexes require at least eight people.
- `dirty: true` is the whole-tree porcelain flag ([line 114](../../../scripts/measure-mixed.mts#L114)), including untracked research. At this method review, `git diff --name-only` was empty and status listed untracked research/private audit paths. The flag does not establish application source edits. Preserve it accurately and record source-input differences separately.

## Decision

Keep the existing artifacts as observed **moderate closed-loop server/client workload with no counted errors**, retain both the quiet first run and the slower repeat, and investigate the repeat's stalls with the planned profile. Do not call this exact replay verification, deletion-under-load acceptance, a saturation test, server-only memory evidence or proof that the 100 ms desktop-main target is met. Strengthening those checks is verification/tooling work; this source review alone proposes no application fix or backend isolation.
