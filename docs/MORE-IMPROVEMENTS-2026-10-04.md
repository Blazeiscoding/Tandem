## Fix boundaries and acceptance

**Q01:** [backup.ts](../packages/server/src/backup.ts), around line 530, releases the target before renaming the old folder and publishing the staged copy. On Windows the focused harness admits an ordinary `createWorkspaceServer` in the missing-path interval and registers a synthetic owner through HTTP. Publication rejects with `EPERM`, rollback does not overwrite the now-existing target, and that target points at the fresh unrelated workspace. The original survives in a superseded folder. Preserve exclusive admission throughout publication and rollback, including a stable identity outside the renamed folder. Accept concurrent start/restore and two restores, plus failed rename and healthy restore. This is not evidence of irrevocable deletion or a public remote restore endpoint.

**Q02:** [workspaceAddressTrust.ts](../packages/ui/src/lib/workspaceAddressTrust.ts), around lines 87–89, uses separate get/set operations; its queue belongs to one Platform instance. Use the storage owner's conditional initialization/atomic update rather than another per-window lock. Accept simultaneous first registrations for different addresses: only one is admitted automatically, and the other requires approval before local-work consumers mount. Preserve deliberate alias approval and failed/corrupt-read refusal. The reproduction holds real IndexedDB read replies after both read absence, uses the production gate and migration, and copies only synthetic IDs/text. It requires concurrent first registration; the normal second-address refusal control passes.

**Q03/Q04:** [notificationPreview.ts](../packages/ui/src/lib/notificationPreview.ts), around lines 150–169, applies an older reply independently of watch delivery and ignores watches before initial load. Fence replies against newer observed state; use an acknowledged current read when ordering is uncertain. [composerPreferences.ts](../packages/ui/src/lib/composerPreferences.ts), around line 38, needs a strict validated read so unreadability retains newline behavior and exposes retry. Accept held initial reads, held save acknowledgements, private updates from another window and record-specific failures. These are caller-level lifetime/read-policy failures; the repaired N02 backend continues keeping the correct durable data.

**Q05/Q06:** [App.tsx](../packages/ui/src/App.tsx), around line 98, writes its in-memory servers list as a whole. Move additions/removals/token replacement into account-aware atomic operations and subscribe/reconcile open windows, retaining explicit removal intent. [JoinScreen.tsx](../packages/ui/src/screens/JoinScreen.tsx), around lines 128 and 689, needs attempt/unmount guards for saved-sign-in and password completion as well as probes. Accept independently stored/forgotten credentials, cancellation then selecting another workspace, expired tokens and late failures. The sign-in harness uses actual App and IndexedDB, with workspace presentation replaced by its public callbacks; no token revocation bypass is established.

**Q07/Q08/Q11:** [SearchDialog.tsx](../packages/ui/src/components/SearchDialog.tsx), around line 144, owns copied results independently of authoritative changes. [MessageListPanel.tsx](../packages/ui/src/components/MessageListPanel.tsx), around line 230, refreshes Pins from loaded timeline pins only. Observe deletion/retention/edit/revocation independently of loaded history and guard held result installation. Accept already-open panels and results arriving after removal, preserving unrelated authorized rows. This concerns previously fetched text, not fresh unauthorized retrieval. [ProfileDialog.tsx](../packages/ui/src/components/ProfileDialog.tsx), around line 28, must stop an abandoned action from navigating. The component and full WorkspaceScreen controls use real HTTP/socket data; the ordinary New message control ignores completion after dismissal.

**Q09/Q10:** [workspace.ts](../packages/client-core/src/workspace.ts), around lines 2526 and 2914, needs latest-intent sequencing for Follow and a request identity for rollback, rather than equality of the cursor value. Accept opposite choices with reordered delivery, repeated identical requests with older failure, and authoritative echoes/reconnect. The controls use an actual loopback server; request ordering or one failure is injected, and stored rows are inspected.

**Q12/Q13:** [index.ts](../apps/desktop/src/main/index.ts), around lines 478–495, must retain/close a created server if post-start policy enforcement fails before its handle reaches the controller. The harness extracts the actual startup callback and uses real SQLite, a write-refusing trigger and a loopback listener. This is an adjacent N12 adapter ownership gap; the previous controller cleanup fixes remain in place. [hosting.ts](../apps/desktop/src/main/hosting.ts), around line 2031, queues shutdown before entering timed cleanup. Give preceding work a bounded cancellation/settlement policy while preserving resource ownership. A held adapter establishes the queue behavior; it does not prove an actual blocked network-share backup or native exit hang.
