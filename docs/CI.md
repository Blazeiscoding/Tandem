# CI duration and caching

Checks keep all seven workspace typechecks, all five unit-test tasks, three builds, both bundle-size guards and the browser E2E suite. Desktop and Container run when their artifact inputs change, including shared UI and client-core code. Ordinary Markdown changes skip these workflows; `docs/INTEGRATIONS.md` runs Checks because the integration contract tests read it.

Linux uses Turbo for the final builds as well as typechecks and tests. The server CLI depends on the web client, so earlier phases already build that client. `pnpm build --concurrency=2` reuses it rather than rebuilding it with a separate package command. Task concurrency is limited to two and each Vitest task gets at most two workers through `VITEST_MAX_THREADS` and `VITEST_MAX_FORKS`; this avoids starting every package's worker pool simultaneously. These variables are declared and hashed only for test tasks. The cache-input check proves that changing worker limits invalidates tests while preserving build/typecheck hashes. Passing Vitest flags through Turbo is avoided because the installed Turbo version also forwards them to dependency builds. Formatting, cache-input verification, bundle guards and browser tests still run on every applicable workflow.

The task-cache archive contains only `.turbo/cache`. Its key includes runner OS and architecture, the actual Node version, the lockfile, Turbo configuration and commit. Compatible earlier archives supply content-addressed entries; Turbo decides whether each task's source, configuration, dependencies and environment still match. Entries expire after seven days and the local cache is capped at 100 MB. Root TypeScript/install configuration and test inputs outside a package are declared explicitly. Package-specific test tasks retain their workspace dependency hashes, including packages that export source without a build script. `node scripts/check-ci-cache.mjs` tests fifteen source/configuration changes and 101 invalidation or preservation assertions in an isolated temporary workspace, and verifies that the web-build hash is the same across all three phases.

[GitHub cache scope](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching#restrictions-for-accessing-a-cache) allows later runs of the same PR to restore its cache and PRs to restore default-branch caches. One PR cannot supply another PR's task cache or overwrite a default-branch cache. The existing dependency-cache workflow on main fills pnpm and Chromium caches; it does not prime Turbo results or Electron downloads. A new PR can therefore still start cold. Jobs running project code use `pull_request` with read-only repository permissions. Artifact deletion runs in a separate job. Cache archives contain task outputs and logs and must not be treated as a security boundary.

Ordinary runtime PRs package Windows with `--win --dir`. This produces `win-unpacked/Gatherline.exe`, which is what desktop E2E launches, while avoiding an unused NSIS installer. PRs changing installer configuration, resources, package manifests, lockfile, install configuration or the selection policy still build the installer. If the base diff cannot be read, selection defaults to full installer coverage. Manual Desktop runs also default to the installer, with an input to choose an unpacked build. Electron and electron-builder downloads use an OS/architecture cache; their self-versioned cache directories allow reuse across lockfile changes within permitted GitHub cache scopes.

The measurements below separate observed work from expected savings. Timing improvements on Actions need a new optimized run before they can be claimed.

| Observation                                    | Measurement                                                | Expected effect                                                                                                                                 |
| ---------------------------------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Prior Linux Checks                             | 437 seconds median; unit tests approximately three minutes | Build reuse saves roughly 9–12 seconds of redundant builds on a comparable cold run. Warm task-cache savings depend on which inputs changed.    |
| Prior Windows installer stage                  | 73–89 seconds, median 79 seconds                           | Ordinary runtime PRs avoid this stage. Packaging changes retain its cost and coverage.                                                          |
| New local unpacked Windows packaging           | 57.65 seconds; packaged E2E passed 3/3                     | Validates the new command and produced executable. Local duration does not predict hosted-runner duration.                                      |
| APT package downloads during one browser setup | 7 minutes 24 seconds                                       | This was a download outlier. Chromium caching does not cache system packages; `install --with-deps` remains necessary on a fresh hosted runner. |

The exact updated typecheck/test/build commands passed locally with `CI=true`: seven typechecks, all 1,460 passing unit/integration tests (two skips), and three builds. The test and final build phases reused the web build. An identical repeat restored every scheduled task from cache and took 1.09 seconds across all three commands. This measures local task reuse; it excludes install/cache transfer, formatting, browser setup and E2E and does not predict total Actions duration. Workflow lint, five installer-selection regressions and the isolated cache checks also pass. Full NSIS packaging and its three desktop E2E checks pass in addition to the unpacked validation above.

Historical Actions evidence includes the [Windows packaging run](https://github.com/Blazeiscoding/SlackOSS/actions/runs/36883563294), [typical Linux run](https://github.com/Blazeiscoding/SlackOSS/actions/runs/36883563144) and [slow browser setup](https://github.com/Blazeiscoding/SlackOSS/actions/runs/36880932839). The browser and container smoke checks remain uncached integration checks. Workflow execution and the resulting remote timings have not been validated by pushing or dispatching a new run from this workspace.
