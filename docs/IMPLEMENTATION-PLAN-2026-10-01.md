**Storage design decision before GL-01–03**

Desktop can centralize transactions in its existing main-process storage owner. For browsers, evaluate an IndexedDB read/write transaction covering initialization and per-record updates; the current synchronous localStorage read/merge/write plus repair watchers does not provide an acknowledged atomic cross-tab contract. Keep migration recoverable and handle quota/unavailable storage. IndexedDB provides scoped transactions; Web Locks coordinates same-origin contexts but requires a secure context, so a Web-Locks-only design would leave plain-HTTP LAN hosting uncovered. These are design inputs, not a demonstrated fix. [IndexedDB terminology](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Basic_Terminology), [Web Locks API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API).

Integrity checking and reference checking are separate: SQLite's integrity check does not validate foreign keys. Decide which checks each supported historical schema requires and measure their cost before using the label “restorable.” [SQLite integrity checking](https://www.sqlite.org/pragma.html#pragma_integrity_check).
